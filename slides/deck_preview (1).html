Speaker notes · slide 2 (~45s)

The problem: banks need to know early which customers may fail to pay. If they only find out after the default, it is too late to help. Our goal is to predict, for each customer, whether they will default next month. The value is proactive monitoring: an analyst can review flagged customers and offer a reminder or a payment plan. We want to be very clear on one point: this is a decision-support prototype. It produces a risk score for a human. It does not approve or reject credit.

3/7
Speaker notes · slide 3 (~50s)

We used the public Default of Credit Card Clients dataset from Kaggle: thirty thousand customers from Taiwan. For each one we know the credit limit, age, six months of payment status, bills and payments, and some demographic fields. The target is simple: did the customer default next month, yes or no. We trained two baselines, Logistic Regression and Random Forest, inside one scikit-learn pipeline. Because most customers do not default, accuracy is misleading, so we compare models on ROC-AUC and also look at recall, precision and F1. Recall matters because a missed defaulter is the costly error.

4/7
Speaker notes · slide 4 (~50s)

This is the MLOps workflow. The training script reads the data, trains both models, and every training execution becomes an MLflow Run. Think of a run as a lab notebook entry that is written automatically: which parameters we used, which metrics we got, the charts, and the model file itself. The script then compares the runs, picks the best ROC-AUC, and registers it in the MLflow Model Registry as credit_default_model with the alias champion. The API always loads the champion. So we can always answer: which model is in use, how was it trained, and how good was it.

Speaker notes · slide 5 (~50s)

We trained both models on the same stratified split of 30,000 customers, where 22% defaulted. The Random Forest won on our selection metric, ROC-AUC: 0.775 against 0.745 for Logistic Regression, and it is also ahead on recall, precision and F1. Recall of 0.58 means it catches about 58% of the customers who actually default; precision of 0.50 means about half of the customers it flags really default. So it is a useful early-warning signal, not a perfect one, and there is a clear trade-off between catching more defaulters and flagging more false alarms. The chart on the right shows the Random Forest curve above the Logistic Regression curve across almost all thresholds. Importantly, nobody picked the winner by hand: the script compared the MLflow runs and registered the Random Forest automatically as the champion model.

Speaker notes · slide 7 (~45s)

To conclude. We built reproducible training, tracked experiments, model versioning, a prediction API and a containerized environment. But a credit risk model affects people. The data contains sex, age and marital status, so bias is a real risk and we would need fairness checks per group. Decisions must be explainable, personal data must be protected, a human must stay in the loop, and after deployment we must monitor for drift. Our takeaway: MLOps is not only about training a model. It is about making the model reproducible, traceable, deployable and governable. Thank you, we are happy to take questions.
